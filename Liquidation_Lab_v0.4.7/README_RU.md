# Liquidation Lab 0.4.8 — операционные исправления

Подготовлено 21 сентября 2026. Это локальная сборка, не опубликованный коммит.
37 тестов проходят: python -m pytest tests scenario_model -q -p no:cacheprovider.

## Изменения относительно 0.4.7

- PAPER ACCOUNT всегда содержит halted_reason, stop_losses_today, entry_state.
  Пустой счёт с daily stop-count 3 явно отображается как halted.
- Решения брокера фиксируются с состояниями счетов в одной транзакции SQLite.
  GET /api/decisions возвращает историю, включая отказы. Тот же DASHBOARD_TOKEN.
- ENTRY DECISION в журнале содержит счёт, символ, setup, сторону, плечо и причину.
- Binance trades/book имеют раздельный статус. Общий online требует обоих каналов.
  Неуспешная подписка не считается подключением; ответ ошибки не игнорируется.
- После разрыва удаляются соответствующие устаревшие сделки/стакан Binance.
  Устаревшая ценовая история не участвует в cross-venue consensus.
- Задержка повторного подключения растёт при коротких соединениях; успешный
  handshake больше не сбрасывает её постоянно на одну секунду.
- Исправлен счётчик переподключений. Добавлены тесты раздельных каналов,
  отказа подписки, cancellation, блокировки счёта, persistence и rollback решений.

Причина исторических обрывов Binance на Railway пока не установлена. Изменения
улучшают обработку и наблюдаемость, но не доказывают устранение внешнего обрыва.
Официальная схема каналов сверена:
https://www.binance.com/en/support/announcement/detail/ebf9b0aa9eca4ff3804eef6fb09ba32a

Никакие стоп-лимиты не сняты. Реальные заявки не добавлены. Proxy-сигналы удалены
ещё в 0.4.7; high-leverage цели и фильтр режима сохранены. Старый рабочий алгоритм
не объявляется восстановленным без исходной версии. AUDIT_RU.md и
STRATEGY_REVIEW_RU.md описывают предыдущий аудит и ограничения модели.

## Запуск

Python 3.11+. Установка: python -m pip install -r requirements.txt
Запуск: python -m app. Панель http://localhost:8000.
DATA_MODE=live — публичные данные, исполнение всегда PAPER_ONLY.
DATA_MODE=synthetic — проверка без интернета.
Настройте DASHBOARD_TOKEN перед публикацией панели. Токен передаётся заголовком
X-Dashboard-Token. SQLite должна быть доступна по DB_PATH; запасная временная база
не создаётся. Перед обновлением постоянной базы требуется её резервная копия.

В /api/status доступны accounts с причинами блокировки, market.feeds с раздельными
каналами Binance, diagnostics с последними решениями. /api/decisions сохраняет
историю между перезапусками. /health описывает работоспособность движка, а не
наличие торгового сигнала. Переход на 0.4.8 не обещает частых входов или прибыль.
