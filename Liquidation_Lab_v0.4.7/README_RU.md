# Liquidation Lab 0.4.7 — исправленная исследовательская сборка

Бумажная торговля на публичных данных. Реальных заявок и клиента с ключами нет.
Проверен локальный запуск, 31 автоматический тестов и 35 секунд публичных потоков
BTC на MEXC / Bybit / Binance. Длительная работа 115 символов и Railway не проверены.

## Запуск

Python 3.11+. Из корня проекта:

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
python -m app
```

Панель: http://localhost:8000. По умолчанию DATA_MODE=live означает реальные
публичные данные, а исполнение всегда виртуальное. Для проверки без интернета
задайте DATA_MODE=synthetic. Для первоначального наблюдения задайте SYMBOLS=BTC_USDT.
Параметры можно задать переменными окружения или файлом .env.

Тесты: `python -m pip install pytest`, затем `python -m pytest tests scenario_model`.

## Что изменено

- Нет выдуманных метаданных, размера контракта, MMR и разрешения API.
- Universe требует проверенные MEXC-метаданные, apiAllowed=true, минимум 200
  завершённых часовых свечей и свежий узкий стакан. Это локальный фильтр;
  проверок возраста 180 дней и оборота 10 млн в рабочем MEXC-пути нет.
- При отсутствии ликвидаций обычный поток сделок не заменяет liquidation-сигнал.
- Bybit поставляет сделки, стакан, OI и ликвидации. Его funding не применяется к MEXC.
- Исчезла подстановка следующего funding через условные 8 часов.
- Ошибка основной SQLite завершает запуск; временная база больше не подменяет счёт.
- Закрытые сделки и состояния счетов фиксируются одной транзакцией каждого тика.
  При ошибке до фиксации изменения счёта откатываются в памяти.
- Проверка метаданных и повтор загрузки недостающей истории выполняются раз в 5 минут.
- /health возвращает HTTP 503, если движок не запустился, отстал или сообщил ошибку.
  Исправность движка не равна допуску к торговле: смотрите /api/status и /api/diagnostics.

## Ограничения и подключение бота

Смотрите AUDIT_RU.md: это обязательное описание границ достоверности, а не
утверждение готовности к реальным деньгам. Funding и ликвидация всё ещё приближённые;
не реализованы полноценные risk tiers, mark-price settlement, округление заявок,
reconciliation с биржей и восстановление пропущенных рыночных событий.

Четыре независимых счёта по 1000 USDT: 20/50/100/200x. Цель 250% относится к
начальной марже позиции, а не ко всему счёту. При текущем стопе 200x закономерно
блокируется. Настройки комиссии — предположение симуляции, не тариф вашего аккаунта.

Бот сигналов может читать /api/status, /api/diagnostics, /api/signals и /api/trades.
Используйте заголовок X-Dashboard-Token и задайте DASHBOARD_TOKEN; без токена панель
публична. Числовой score не является вероятностью успеха или прогнозом доходности.
Превращение сигнала в реальную заявку требует отдельного execution-контура из отчёта.

Для Railway сохранён Dockerfile: подключите постоянный Volume /data. Перед обновлением
сделайте резервную копию SQLite. Схема БД и названия счетов совместимы, но статистику
0.4.6 и 0.4.7 нельзя смешивать: правила допуска и состав сигналов изменились.
Для чистого эксперимента задайте новый DB_PATH, например /data/paper_v047.db.
